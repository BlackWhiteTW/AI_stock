# 主模型 vs 個股模型訓練對比

## 📊 訓練參數對比

### 主模型訓練 (Base Model)
```python
訓練輪數 (Epochs):
  - 標準模式: 120 epochs（不使用遷移學習）
  - 高波動: 250 epochs

數據量:
  - 增強版: 25 支標的 × ~5000 天 = 125,000 天
  - 標準版: 8 支標的 × ~2000 天 = 16,000 天
  - 數據增強後翻倍: ~32,000-250,000 天

訓練樣本數:
  - 增強版: ~247,500 個樣本（扣除 lookback）
  - 標準版: ~31,000 個樣本
```

### 個股模型訓練 (Stock Model)
```python
訓練輪數 (Epochs):
  - 使用遷移學習: 100 epochs（正常）/ 200 epochs（高波動）
  - 不使用遷移學習: 120 epochs（正常）/ 250 epochs（高波動）

數據量:
  - 單支股票: ~1000-3000 天
  - 無數據增強

訓練樣本數:
  - 約 940-2940 個樣本（扣除 60 天 lookback）
```

## ⏱️ 實際訓練時間對比

### 影響訓練速度的關鍵因素

#### 1️⃣ **訓練樣本數量** ⭐⭐⭐⭐⭐
```
主模型：247,500 個樣本（增強版）
個股模型：1,500 個樣本（典型台股）

→ 主模型需要處理的樣本是個股的 165 倍！
```

#### 2️⃣ **Epoch 數量** ⭐⭐⭐
```
主模型：120 epochs（不使用遷移學習）
個股模型（遷移）：100 epochs
個股模型（無遷移）：120 epochs

→ 差異不大
```

#### 3️⃣ **早停機制 (Early Stopping)** ⭐⭐⭐⭐
```python
patience = 30  # 正常股票
patience = 60  # 高波動股票

如果驗證損失連續 patience 輪未改善，提前結束訓練
```

#### 4️⃣ **每個 Epoch 的計算量**
```
時間 = 樣本數 ÷ Batch Size × 每批次處理時間

主模型：247,500 ÷ 64 × t = 3,867 批 × t
個股模型：1,500 ÷ 64 × t = 23 批 × t

→ 主模型每個 epoch 需要處理 168 倍的批次數！
```

## 🔍 為什麼您可能覺得主模型更快？

### 可能原因 1: 早停機制提前結束
```
主模型使用大量多樣化數據，可能在前 10-20 個 epoch 就收斂
個股模型數據較少，需要更多 epoch 才能充分學習

實際訓練輪數範例:
  主模型: 15/120 epochs (早停)
  個股模型: 85/100 epochs (幾乎跑滿)
```

### 可能原因 2: UI 進度顯示差異
```python
# 主模型的進度回調
progress_callback(idx, len(stock_list), 0, 0)  # 數據收集階段
progress_callback(epoch, num_epochs, loss, elapsed)  # 訓練階段

# 個股模型的進度回調
progress_callback(epoch, total_epochs, loss, train_elapsed)

→ 主模型前 30% 是數據下載，可能讓整體進度看起來更快
```

### 可能原因 3: GPU 利用率差異
```
主模型數據量大 → 更大的 Batch 並行處理 → GPU 利用率高 → 單位時間效率高
個股模型數據量小 → Batch 較小 → GPU 未充分利用 → 相對效率低
```

## 📈 實際訓練時間估算

### 主模型（增強版）
```
數據下載: 2-5 分鐘（25 支標的）
數據增強: 30-60 秒
訓練階段: 
  - CPU: 15-30 分鐘（假設早停在 20 epoch）
  - GPU (CUDA): 5-10 分鐘

總計: ~10-35 分鐘（依硬體和早停時機）
```

### 個股模型（台積電為例）
```
數據下載: 10-30 秒
訓練階段:
  - CPU (無遷移): 5-10 分鐘（120 epochs）
  - CPU (有遷移): 2-5 分鐘（100 epochs，前 30 凍結）
  - GPU (CUDA): 30-90 秒

總計: ~1-10 分鐘（依遷移學習和硬體）
```

## 💡 優化建議

### 如果主模型訓練太慢

1. **使用標準模式** (8 支股票而非 25 支)
2. **減少歷史天數** (2000 天而非 5000 天)
3. **關閉數據增強**
4. **使用 GPU** (CUDA 加速)
5. **調低 patience** (提早早停)

### 如果個股模型訓練太慢

1. **確認已訓練主模型** (啟用遷移學習)
2. **使用 GPU** 
3. **調低 Epoch** (100 → 50)
4. **增加 Batch Size** (64 → 128)

## 📝 結論

**主模型通常不會比個股模型更快！**

- **數據量**: 主模型 >> 個股模型
- **計算量**: 主模型 >> 個股模型
- **實際時間**: 主模型 > 個股模型 (大部分情況)

如果您觀察到主模型更快，可能是：
1. ✅ 早停機制提前結束（這是好事！）
2. ✅ GPU 加速效果顯著
3. ⚠️ 個股模型沒有使用遷移學習
4. ⚠️ UI 進度顯示造成的錯覺

建議您在「訓練歷史與統計」中查看實際訓練時間 (duration) 來確認！
